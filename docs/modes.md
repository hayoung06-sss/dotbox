# 합체·분리 모드와 하드웨어 확장 명세 (초안 v0.1)

> 상태: **제안**. 아직 구현하지 않았다. 구현하면서 바뀌는 내용은 이 문서를 먼저 고친다.
>
> **범위**: 지금 구현 대상은 2인 플레이에 필요한 3장(화면 레이아웃)과 4장(합체 상태)뿐이다.
> 5장(상대 위치)과 6장(하드웨어 확장)은 **나중에 추가할 수 있게 설계를 열어 두는 것**까지만 한다.
> 엔진 API를 만들 때 이 기능들이 들어갈 자리(모듈별 구성 조회, 확장 데이터 전송 칸)를 막지 않는 것이 목표다.

## 1. 목적

DotBox의 두 모듈은 붙여서(합체) 쓸 수도 있고 떼어서(분리) 쓸 수도 있다. 분리는 다음 용도를 위한 기능이다.

- **2인 플레이**: 두 사람이 모듈을 하나씩 들고 각자 자기 화면을 본다. 상대에게 화면을 가리거나, 편한 자세로 플레이한다.
- **창의적 활용**: 두 모듈의 상대적 위치나 거리, 각 모듈에 추가한 하드웨어(센서, 진동 모터 등)를 게임에 활용한다.

엔진은 이 두 가지를 모두 받아 줄 수 있어야 하고, 하드웨어를 추가할 때 엔진 코드를 고치지 않아도 되어야 한다.

## 2. 기본 원칙

- **분리는 물리적 상태일 뿐이다.** 분리해도 ESP-NOW 연결, 같은 이미지, 왼쪽 마스터/오른쪽 슬레이브 구조([pairing.md](pairing.md))는 그대로다.
- **분리를 모르는 게임도 그대로 동작한다.** 합체·분리 상태를 쓰지 않는 게임은 지금처럼 32×16 화면에 그리면 된다.
- **분리를 활용하는 게임은 직접 선택한다.** 엔진은 합체 상태를 알려 주고 모듈별 화면을 제공할 뿐, 레이아웃을 자동으로 바꾸지 않는다.

## 3. 화면 레이아웃

| 레이아웃 | 논리 화면 | 용도 |
|---|---|---|
| `Wide` (기본) | 32×16 하나. x 0~15는 왼쪽, 16~31은 오른쪽 | 합체해서 넓은 화면으로 쓰는 게임. 분리해도 그대로 동작한다(예: 핑퐁) |
| `Mirrored` | 16×16 하나를 두 패널에 똑같이 표시 | 두 사람이 같은 화면을 봐야 할 때 |
| `Split` (추가) | **독립된 16×16 화면 2개.** 게임이 모듈마다 다른 내용을 그린다 | 각자 자기 화면을 보는 2인 게임. 상대에게 보여 주면 안 되는 정보 |

- `Split`에서 게임은 각 화면의 지역 좌표(0~15)로 그린다. 예상 API: `frame.view_mut(Side::Left)`가 16×16 그리기 대상을 돌려준다.
  자세한 형태는 게임 API 명세에서 정한다.
- 메모리 배치는 `Wide`와 같다(32×16 버퍼의 왼쪽 절반과 오른쪽 절반). 레이아웃은 게임이 좌표를 해석하는 방식만 바꾼다.
- `Split` 화면에 그리는 내용은 **화면 표시만** 가린다. 오른쪽 모듈도 같은 게임 상태를 받으므로 데이터 수준의 비밀은 아니다.

### 3.1 패널 회전

분리해서 들면 두 사람이 마주 보거나 모듈을 세워 들 수 있다. 모듈마다 패널 회전(0°, 90°, 180°, 270°)을 따로 설정할 수 있게 한다.

- 회전은 엔진이 출력 단계에서 적용한다. 게임 좌표계는 바뀌지 않는다.
- 게임이 설정할 수 있다. 예: 마주 보는 게임이 오른쪽 모듈을 180° 회전.
- 케이스에 조립하면서 생기는 고정 방향 보정은 보드 설정에 따로 둔다. 둘은 서로 독립이다.

## 4. 합체 상태

```
DockState = Docked | Undocked | Unknown
```

- 결합 감지 홀센서(GPIO26)가 있으면 그 값으로 정한다. 디바운스를 거친다.
- 센서가 없으면 항상 `Unknown`이다. 게임은 `Unknown`을 받아도 동작해야 한다.
- 센서는 양쪽 모듈에 있을 수 있다. 판정은 마스터가 하고, 두 값이 다르면 `Unknown`으로 본다.
- 상태가 바뀌면 다음 틱 입력에 이벤트로 전달한다. 게임은 현재 상태 조회와 변경 이벤트를 모두 쓸 수 있다.

## 5. 상대 위치 정보

엔진이 기본으로 제공하는 정보:

| 정보 | 출처 | 비고 |
|---|---|---|
| 합체 상태 | 홀센서 | 4장 |
| 신호 세기(RSSI) | ESP-NOW 수신 정보 | 필터링한 dBm 값. 거리를 **대략** 짐작하는 데만 쓴다. 장애물, 방향, 손에 따라 크게 흔들린다 |

방향이나 정확한 거리 같은 정보가 필요하면 6장의 확장 하드웨어(IMU, 적외선, 초음파 등)로 추가한다.

## 6. 하드웨어 확장

### 6.1 모듈 하드웨어 구성(capabilities)

같은 이미지를 써도 **모듈마다 하드웨어가 다를 수 있다.** 오른쪽 부저는 선택 부품이고, 확장 장치도 한쪽에만 달 수 있다.

- 각 모듈은 부팅할 때 자기 구성을 정리해 핸드셰이크 `Hello`에 담아 보낸다([pairing.md](pairing.md) 3.2).
- 구성 항목: 부저, 홀센서, 상태 LED 유무와 확장 장치 목록(ID, 데이터 크기).
- 게임은 `capabilities(Side)`로 모듈별 구성을 조회한다. 필요한 장치가 없으면 게임이 대체 동작을 정한다.
- 오른쪽에 부저가 있으면 소리를 모듈별로 낼 수 있다(분리 시 각 플레이어에게 소리). 지정하지 않은 소리는 왼쪽에서 낸다.

### 6.2 확장 장치 인터페이스

확장 장치는 `dotbox-core`의 트레잇을 구현해 등록한다. 엔진과 게임 공통 코드는 고치지 않는다.

```rust
// 형태 예시. 이름과 시그니처는 게임 API 명세에서 확정한다.
pub trait Extension {
    /// 이 장치를 구분하는 ID. 게임과 장치 드라이버가 같은 값을 쓴다.
    fn id(&self) -> ExtensionId;
    /// 입력 장치: 이번 틱의 샘플을 `out`에 쓰고 길이를 돌려준다.
    fn sample(&mut self, out: &mut [u8]) -> Result<usize>;
    /// 출력 장치: 마스터가 보낸 명령을 적용한다(예: 진동).
    fn apply(&mut self, command: &[u8]) -> Result<()>;
}
```

- **등록**: 펌웨어 `main`(게임 쪽)이 실행기를 부르기 전에 장치를 등록한다. 드라이버는 게임 저장소나 별도 crate에 둔다.
  `dotbox-sim`과 테스트에는 같은 트레잇의 가짜 구현을 등록한다.
- **전송**: 오른쪽 모듈의 입력 샘플은 조이스틱 입력과 함께 매 틱 마스터로 간다. 출력 명령은 마스터가 상태 메시지에 실어 보낸다.
  모듈당 확장 데이터 크기에는 상한을 둔다(값은 동기화 명세에서 정한다).
- **실행 문맥**: `sample`과 `apply`는 엔진 루프 스레드에서 부른다. 장치 인터럽트가 필요하면 데이터를 복사해 큐로 넘기기만 한다.
- 매 틱 경로이므로 힙 할당을 하지 않는다.

### 6.3 확장용 예비 핀

현재 핀 배치에서 남는 핀이다. **실제 보드(CMODULE-43)의 핀 배치와 PSRAM 유무를 확인한 뒤 확정한다.**

| 용도 | 핀 | 비고 |
|---|---|---|
| I2C (권장 확장 버스) | GPIO21 (SDA), GPIO22 (SCL) | IMU, 거리 센서 등 여러 장치를 한 버스에 연결 |
| 범용 디지털 | GPIO4, 16, 17, 18, 19, 23 | GPIO16/17은 PSRAM이 있는 모듈에서는 쓸 수 없다 |
| 아날로그 입력 | GPIO34, 35, 36, 39 (ADC1, 입력 전용) | Wi-Fi와 함께 쓸 수 있는 ADC1 |
| 쓰지 않음 | GPIO0, 2, 5, 12, 15 (스트래핑), 6~11 (플래시), 1/3 (UART0 로그) | |

## 7. 시뮬레이터

- 두 패널을 따로 그리고, 패널 사이 간격과 패널별 회전을 바꿀 수 있다.
- 키 하나로 합체/분리 상태를 바꾼다(`Docked` ↔ `Undocked`, 센서 없음 = `Unknown`).
- RSSI 값을 조절하는 입력을 둔다.
- 확장 장치는 가짜 구현을 등록하고, 값을 키보드나 디버그 패널로 바꿀 수 있게 한다.

## 미결 사항

- `Split` 그리기 API와 확장 장치 API의 정확한 형태. 게임 API 명세에서 정한다.
- 확장 데이터 크기 상한과 전송 주기. 동기화 명세에서 정한다.
- 홀센서를 필수 부품으로 바꿀지(지금은 선택).
- RSSI가 게임에 쓸 만한지 실기기에서 측정한다.
- 패널 회전을 플레이어가 기기에서 직접 바꿀 수 있게 할지.
