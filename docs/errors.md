# 런타임 오류 처리 정책 (초안 v0.1)

> 상태: **제안**. 아직 구현하지 않았다.

## 1. 원칙

- **기기에서는 표시하지 않고 재시작한다.** 기기에서 생긴 런타임 오류는 그 자리에서 고칠 수 없다.
  오류를 화면에 띄우는 코드를 넣는 대신, 시리얼 로그를 남기고 재시작해서 다시 플레이할 수 있게 한다.
- **개발 환경(시뮬레이터, 테스트)에서는 드러내고 멈춘다.** 개발자가 고칠 수 있는 곳이므로 오류를 숨기거나
  자동으로 다시 시작하지 않는다.
- 재시작은 **복구할 수 없는 오류**에만 쓴다. 복구할 수 있는 오류는 평소처럼 `Result`로 처리한다.

## 2. 오류 분류

| 분류 | 예 | 처리 |
|---|---|---|
| 복구 가능 | 링크 끊김(`Disconnected`), 송신 큐 초과(`QueueFull`), 저장 값 없음 | 엔진·게임이 처리한다. 연결 상태 표시([pairing.md](pairing.md) 4장)처럼 정상 동작의 일부다 |
| 설정 문제 | 두 모듈의 펌웨어 불일치, 역할 미정 | 재시작해도 해결되지 않는다. 상태 LED와 역할 선택 화면으로 알려 준다(pairing.md) |
| 복구 불가 | panic, 실행기까지 올라온 `Err`, 엔진 루프 멈춤(워치독), 메모리 부족 | **기기: 재시작. 개발 환경: 출력 후 종료** |

## 3. 기기 (`dotbox-esp`)

### 3.1 재시작 경로

| 원인 | 처리 |
|---|---|
| panic | ESP-IDF panic 핸들러가 로그를 남기고 재부팅한다(`sdkconfig.defaults`에 `CONFIG_ESP_SYSTEM_PANIC_PRINT_REBOOT=y`) |
| 엔진 루프·씬이 돌려준 `Err` | 실행기가 오류와 발생 위치를 로그로 남기고 `esp_restart()`를 부른다 |
| 엔진 루프 멈춤 | 엔진 루프 스레드를 태스크 워치독에 등록하고, 시간을 넘기면 panic 후 재부팅한다 |

- 그래서 `dotbox_esp::run`은 반환하지 않는다(`-> !`).
- 재시작하는 동안 매트릭스와 부저는 별도 처리를 하지 않는다. 부팅하면서 초기화된다.

### 3.2 부팅 로그

부팅할 때 다음을 시리얼로 출력한다. 개발자는 `dotbox monitor`로 본다.

- 리셋 원인(`esp_reset_reason`): 전원, panic, 워치독, 소프트웨어 재시작 등
- 비정상 재시작 연속 횟수: RTC 영역(`RTC_NOINIT`)에 두고 정상 종료 없이 재시작할 때마다 1씩 늘린다.
  연결에 성공하고 일정 시간 실행되면 0으로 되돌린다.
- 빌드 식별자(pairing.md 3.1)

### 3.3 재시작이 다른 기능에 주는 영향

- 상대 모듈은 연결이 끊긴 것으로 보고 `Searching`으로 돌아간다. 재시작한 모듈이 올라오면 핸드셰이크를 다시 한다.
- 왼쪽(마스터)이 재시작하면 진행 중인 게임은 사라지고 처음부터 시작한다.
- 저장(`Storage`) 중에 재시작해도 이전 값이 깨지지 않아야 한다. 쓰기는 새 값을 다 쓴 뒤 교체하는 방식으로 한다.

## 4. 개발 환경 (`dotbox-sim`, 테스트)

- panic은 그대로 둔다. 메시지와 위치가 터미널에 출력되고 프로세스가 끝난다.
- 실행기까지 올라온 `Err`는 터미널에 출력하고 종료 코드 1로 끝낸다. `dotbox_sim::run`은 `Result`를 돌려준다.
- 기기에서 재시작이 일어나는 상황(상대 모듈 재시작 등)은 가짜 `Link`로 재현해 테스트한다.

## 미결 사항

- 태스크 워치독 시간. 가장 긴 정상 작업(플래시 쓰기 등)보다 길어야 한다.
- 재시작이 끝없이 반복될 때의 처리. 지금은 따로 막지 않고 연속 횟수만 기록한다.
  필요하면 일정 횟수가 넘을 때 재시작 사이에 대기 시간을 둔다.
- ESP-IDF 코어 덤프를 플래시에 남겨 나중에 PC로 꺼내 볼지.
