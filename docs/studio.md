# DotBox Studio 명세 (제안 v0.1)

> 상태: **제안**. Studio 담당과 엔진 담당이 합의하면 "확정"으로 바꾸고, 새 CLI 명령은 `docs/cli.md`로 옮긴다.
> 에셋 형식(5장)은 엔진 런타임 타입과 맞물리므로 합의 전에 구현하지 않는다.

## 1. 목적

Studio는 지금 스프라이트, 글꼴, 효과음, 기기 패널의 네 가지 **도구 모음**이다. 각 도구는 동작하지만 게임 개발 흐름에 연결되어 있지 않다.

| 지금 | 문제 |
|---|---|
| 그린 스프라이트, 만든 멜로디를 저장할 수 없다 | 작업 결과가 창을 닫으면 사라지고 게임에 들어갈 길이 없다 |
| 프로젝트 개념이 없다. 기기 패널에 경로를 직접 입력한다 | `dotbox studio <DIR>`이 넘기는 경로도 쓰지 않는다 |
| 기기 패널이 CLI를 실행하고 결과를 문자열로 보여 준다 | 진행 상황이 안 보이고, 결과를 구조로 다룰 수 없다 |
| 도구끼리 상태가 섞인다(글꼴 미리보기 색 = 스프라이트 브러시 색) | 화면마다 무엇을 편집하는지 불분명하다 |

이 문서는 Studio를 **게임 프로젝트를 열어 에셋을 만들고, 빌드하고, 기기에 올리는 하나의 작업 공간**으로 바꾸기 위한 기능과 형식을 정한다.

## 2. 원칙

`tools/dotbox-studio/AGENTS.md`의 설계 원칙을 그대로 따른다. 이 문서에서 특히 중요한 것:

1. **CLI 대응.** 파일을 만들거나 바꾸는 작업, 빌드·기기에 영향을 주는 작업은 같은 일을 하는 `dotbox` 명령이 있어야 한다(7장).
   화면 안에서만 의미가 있는 동작(확대, 미리 듣기, 선택, 실행 취소)은 예외다.
2. **로직은 `dotbox-tools`.** 형식 해석, 검사, 변환, 프로젝트 조작은 `dotbox-tools` 함수이고 Studio는 그 함수를 직접 부른다.
   CLI 출력을 파싱하지 않는다.
3. **원본만 편집.** Studio는 `assets/`의 원본 파일만 쓴다. Rust 코드는 게임의 `build.rs`가 생성한다.
4. **사람이 읽고 diff할 수 있는 원본.** 이미지는 PNG, 나머지는 TOML. 바이너리 전용 형식을 만들지 않는다.
5. **결정적 출력.** 같은 원본과 같은 도구 버전이면 생성 결과가 바이트 단위로 같다.

## 3. 화면 구성

```
┌ 도구 모음: [프로젝트 ▾] [▶ 실행] [빌드] [플래시 ▾]  상태: 엔진 0.1.0 · 왼쪽 COM5 · 오른쪽 COM6 ┐
├───────────────┬───────────────────────────────────────────────────────────┤
│ 프로젝트 탐색기 │ 편집기 탭: [개요] [player.png ●] [jump.sound.toml] ...      │
│  개요          │                                                           │
│  에셋          │   (열린 파일의 편집기)                                       │
│   sprites/    │                                                           │
│   sounds/     │                                                           │
│   fonts/      │                                                           │
│   icon.png    │                                                           │
│  기기          │                                                           │
├───────────────┴───────────────────────────────────────────────────────────┤
│ 아래 패널: [출력] [문제 3] [시리얼: 왼쪽 | 오른쪽]                                │
└───────────────────────────────────────────────────────────────────────────┘
```

- 프로젝트가 없으면 **시작 화면**(4.1)을 보여 준다.
- 편집기는 **파일 단위 탭**이다. 저장하지 않은 탭은 `●`로 표시하고, 닫거나 종료할 때 확인한다.
- 아래 패널은 빌드·실행 출력, 문제 목록(4.7), 두 모듈의 시리얼 로그를 보여 준다.

## 4. 기능

### 4.1 프로젝트 열기와 만들기

- **실행 인자**: `dotbox-studio [DIR]`. `DIR`이 있으면 `Project::discover(DIR)`로 연다. 실패하면 시작 화면에 오류를 보여 준다.
- **시작 화면**: 최근 프로젝트 목록, [새 프로젝트], [폴더 열기].
  - 최근 목록에서 사라진 경로는 흐리게 표시하고 목록에서 지울 수 있게 한다.
- **새 프로젝트**: `dotbox new`와 같은 입력을 받는다. 이름, 위치, 엔진 소스(git / 로컬 경로), 펌웨어 포함 여부, git 초기화.
  - 이름은 입력하는 동안 `manifest::validate_name`으로 검사해 바로 알려 준다.
  - 위치에 한글·공백·OneDrive가 있으면 `doctor`의 경로 점검과 같은 기준으로 **만들기 전에** 경고한다.
  - 만든 뒤 바로 연다.
- **프로젝트 닫기/전환**: 저장하지 않은 파일이 있으면 확인한다.

### 4.2 개요

프로젝트를 열면 처음 보이는 탭. 한 화면에서 프로젝트 상태를 확인한다.

| 항목 | 출처 |
|---|---|
| 이름, 경로, `[paths]` | `dotbox.toml` |
| 엔진 버전과 CLI 버전 일치 여부 | `doctor`의 `engine.version` 점검 |
| 환경 점검 요약(오류·경고 수, 펼치면 항목별) | `doctor::run` → `Report` |
| 에셋 수와 검사 결과 | `assets::check` (5장, 7장) |
| 포트 설정, 모듈별 마지막 플래시 `build_id` | `.dotbox/local.toml` |
| 현재 빌드의 `build_id`와 기기 이미지 일치 여부 | 마지막 빌드 ELF와 `[flashed]` 비교 |

### 4.3 프로젝트 설정

- `dotbox.toml` 편집 폼. 프로젝트 이름, `[paths]`. 저장 전에 `Manifest::parse`로 검사한다.
- 개인 설정(`.dotbox/local.toml`)의 왼쪽/오른쪽 포트. 감지된 포트 목록에서 고른다.
- 이름을 바꾸면 패키지 이름(`<name>`, `<name>-sim`, `<name>-firmware`)도 바뀐다.
  1차에서는 이름 변경을 막고 안내만 한다(미결 사항).

### 4.4 에셋 탐색기

- `assets/`를 종류별로 보여 준다(5장의 디렉토리 구조). 종류를 모르는 파일은 "기타"로 보여 주고 무시한다.
- 작업: 새로 만들기(종류 선택 → 이름 → 기본 원본 생성), 이름 바꾸기, 복제, 삭제(확인 후), 탐색기에서 열기.
- 에셋 이름은 생성 코드의 식별자가 되므로 규칙을 둔다. 소문자, 숫자, `_`이고 소문자로 시작한다(`player_run` → `PLAYER_RUN`).
- **외부 변경 감지**: 다른 프로그램(이미지 편집기, git)이 파일을 바꾸면 다시 읽는다.
  열린 탭에 저장하지 않은 변경이 있으면 어느 쪽을 남길지 묻는다.
- 검사 오류가 있는 에셋은 탐색기에 표시하고, 문제 패널에서 클릭하면 해당 파일을 연다.

### 4.5 편집기

모든 편집기에 공통:

- 열기/저장(Ctrl+S)/모두 저장, 실행 취소/다시 실행(Ctrl+Z/Ctrl+Y, 파일마다 따로).
- 편집 명령은 GUI와 분리된 로직(명령 객체)으로 만들어 GUI 없이 테스트한다.
- 미리보기는 `dotbox-core`로 그린다. 실기기 밝기 미리보기는 도구 모음의 전역 설정 하나로 둔다.

| 편집기 | 대상 | 기능 |
|---|---|---|
| 스프라이트 | `sprites/*.png` | 크기 지정(1×1 ~ 32×16), 연필, 지우개, 채우기, 스포이드, 직선, 사각형, 선택·이동, 투명색. 애니메이션 프레임 추가·삭제·순서·프레임별 시간, 재생 미리보기 |
| 아이콘 | `icon.png` | 16×16 고정 스프라이트 편집기. 메뉴 화면 모양으로 미리보기 |
| 효과음 | `sounds/*.sound.toml` | 지금 기능 + 파일 저장. 부저가 낼 수 있는 주파수 범위 밖이면 경고 |
| 글꼴 | `fonts/*.font.toml` | 원본 글꼴 파일 선택, 픽셀 크기, 임계값, 문자 집합, 라이선스. 글자별 결과 표와 문장 미리보기(기준선 정렬) |
| 화면 | (선택, 3단계) | 32×16 화면에 스프라이트·글자를 배치해 보는 장면 미리보기. 파일로 저장하지 않는다 |

### 4.6 실행, 빌드, 기기

- **실행**: `cargo::run_sim`을 자식 프로세스로 띄운다. Studio는 멈추지 않는다. [중지] 버튼으로 끝낼 수 있다.
  Studio 안에 게임 화면을 넣지 않는다(시뮬레이터 창이 맡는다).
- **빌드·플래시**: 진행 중 출력을 **줄 단위로 바로** 아래 패널에 보여 준다. 끝나면 결과(`FlashReport`: 모듈별 포트, `build_id`)를 개요에 반영한다.
  - 대상: 왼쪽 / 오른쪽 / 양쪽. 포트는 설정값을 기본으로 쓰고, 감지된 포트에서 모듈별로 고른다.
  - 실행 중에는 같은 프로젝트의 다른 빌드·플래시를 막는다.
- **시리얼 로그**: 왼쪽과 오른쪽 모듈 로그를 탭 또는 나란히 보여 준다. 일시 정지, 지우기, 파일로 저장, 검색.
  재시작(복구할 수 없는 오류 → 재부팅, `docs/errors.md`)이 보이면 강조한다.
- **연결 확인**: 포트별로 어느 모듈(역할 레코드)이 연결됐는지 보여 준다(펌웨어가 생긴 뒤).

### 4.7 문제 패널

다음 결과를 한곳에 `종류 · 위치 · 메시지` 목록으로 보여 준다. 항목을 누르면 해당 파일이나 설정 화면을 연다.

- `doctor` 점검의 오류·경고(`Report`의 `Check`).
- 에셋 검사 오류(파일, 가능하면 위치: 프레임 번호, 음표 번호, 글자).
- `cargo` 빌드 오류. `--message-format=json`의 진단을 쓴다(사람용 출력을 파싱하지 않는다).

## 5. 에셋 원본 형식 (합의 필요)

```
assets/
  icon.png                    # 메뉴 아이콘. 16×16. GameConfig::icon
  sprites/<name>.png          # 스프라이트. 애니메이션이면 프레임을 가로로 이어 붙인다
  sprites/<name>.sprite.toml  # (선택) 프레임 크기와 시간
  sounds/<name>.sound.toml    # 효과음
  fonts/<name>.font.toml      # 글꼴 변환 설정
  fonts/<file>.ttf|.otf       # 글꼴 원본
```

**스프라이트**: RGBA PNG. 알파가 0이면 투명(그리지 않음), 그 외 알파는 오류다(LED에는 반투명이 없다). 크기는 32×16 이하.

```toml
# sprites/player_run.sprite.toml (없으면 프레임 1개, PNG 전체 크기)
frame_width = 8
frame_height = 8
frame_ms = [100, 100, 150]   # 프레임 수와 같은 길이. 하나만 쓰면 모든 프레임에 적용
```

**효과음**:

```toml
# sounds/jump.sound.toml
notes = [
  [523, 120],   # [freq_hz, duration_ms]. freq_hz = 0이면 쉼표
  [784, 80],
]
```

**글꼴**:

```toml
# fonts/digits.font.toml
source = "PressStart2P.ttf"   # 같은 디렉토리의 글꼴 파일
pixel_size = 8
threshold = 128
charset = "0123456789:"
license = "OFL-1.1"           # 필수. 배포 조건을 함께 기록한다
```

**생성 코드**: 게임의 `build.rs`가 `dotbox_tools::assets::generate`를 불러 `OUT_DIR/assets.rs`를 만들고, 게임은 다음처럼 쓴다.

```rust
mod assets { include!(concat!(env!("OUT_DIR"), "/assets.rs")); }
// assets::PLAYER_RUN: Sprite, assets::JUMP: Sound, assets::DIGITS: Font, assets::ICON: Icon
```

- `Sound`와 `Icon`은 엔진에 이미 있다. `Sprite`와 `Font` 런타임 타입, 그리기 함수(`FrameBuffer`에 스프라이트·글자 그리기)는 **엔진에 새로 필요하다**(8장).
- 생성 코드는 모두 `static` 데이터다. 매 틱 경로에서 힙 할당을 하지 않는 엔진 규칙을 지킨다.
- `dotbox new` 템플릿에 `build.rs`와 빈 `assets/` 구조를 넣는다.

## 6. Studio 설정 파일

| 파일 | 위치 | 내용 |
|---|---|---|
| 사용자 설정 | OS 설정 디렉토리의 `dotbox/studio.toml`(Windows: `%APPDATA%\dotbox\studio.toml`) | 최근 프로젝트, 창 크기, 실기기 밝기 미리보기 값 |
| 프로젝트별 UI 상태 | `.dotbox/studio.toml`(gitignore 대상) | 열려 있던 탭, 탐색기 펼침 상태 |

공유해야 하는 값(포트를 뺀 프로젝트 설정)은 `dotbox.toml`에만 둔다. Studio 전용 파일에 두지 않는다.

## 7. CLI·`dotbox-tools` 대응

### 7.1 기능 대응표

| Studio 기능 | CLI | `dotbox-tools` | 상태 |
|---|---|---|---|
| 새 프로젝트 | `dotbox new` | `project::create` | 있음 |
| 개요 | `dotbox info [--json]` | `project::info` → `ProjectInfo` | **신규** |
| 환경 점검 | `dotbox doctor [--json]` | `doctor::run` | 있음 |
| 설정(포트) | `dotbox config get/set <KEY> [VALUE]` | `local::LocalConfig` 읽기·쓰기 | **신규** |
| 에셋 목록 | `dotbox assets list [--json]` | `assets::list` | **신규** |
| 에셋 만들기 | `dotbox assets new <KIND> <NAME>` | `assets::create` | **신규** |
| 에셋 검사 | `dotbox assets check [--json]` | `assets::check` | 2단계 예정 → 형식 확정 |
| 코드 생성 | `dotbox assets build --out <DIR>` | `assets::generate` | 2단계 예정 → 형식 확정 |
| 글꼴 변환 | `dotbox font preview <FONT.toml> <TEXT>` | `assets::font` | 2단계 예정 |
| 실행 | `dotbox run` | `cargo::run_sim` | 있음 |
| 빌드 | `dotbox build` | `cargo::build_firmware` | 있음 → 진행 출력 필요 |
| 플래시 | `dotbox flash` | `device::flash` | 있음 → 진행 출력 필요 |
| 시리얼 로그 | `dotbox monitor [--side both]` | `device::monitor` | 있음 → 양쪽 동시는 2단계 |

PC 스피커 재생, 확대, 실행 취소 같은 화면 전용 동작은 CLI 대응이 없다(2장 1번 예외).

### 7.2 `dotbox-tools`에 필요한 변경

- **진행 출력.** 지금 `cargo::*`, `device::*`는 자식 프로세스 출력을 터미널에 그대로 넘긴다.
  출력 줄과 단계를 받는 **이벤트 수신자**를 인자로 받게 바꾼다. CLI는 터미널에 쓰는 수신자를, Studio는 채널로 보내는 수신자를 넘긴다.

  ```rust
  pub enum Event { Step(String), Line { stream: Stream, text: String }, Finished(Result<()>) }
  pub trait Sink: Send { fn event(&mut self, event: Event); }
  ```

- **취소.** 오래 걸리는 작업(빌드, 플래시, 시뮬레이터, 모니터)은 취소 핸들을 돌려준다. 취소하면 자식 프로세스를 끝낸다.
- **구조화된 결과.** 새 함수는 사람용 문자열이 아니라 타입을 돌려준다(`ProjectInfo`, `Vec<AssetEntry>`, `Vec<Diagnostic>`).
  CLI의 `--json`은 이 타입을 그대로 직렬화한다.
- **에셋 모듈.** 5장 형식의 해석·검사·생성. GUI 의존성 없이 게임 `build.rs`에서도 쓴다.
  지금 Studio 안에 있는 글꼴 변환 로직(`font.rs`)은 여기로 옮긴다.

## 8. 역할 분담

| 작업 | 담당 |
|---|---|
| Studio 화면, 편집기, 시작 화면, 탐색기, 패널 | Studio 담당 |
| 에셋 형식 확정(5장) | 둘이 합의 |
| `dotbox-tools`: `assets`, `info`, `config`, 진행 이벤트·취소 | 엔진 담당(Studio 담당이 PR로 기여 가능, 엔진 담당 리뷰) |
| `dotbox-cli`: 신규 명령과 `docs/cli.md` 갱신 | 엔진 담당 |
| `dotbox-core`: `Sprite`, `Font` 타입과 그리기 함수 | 엔진 담당 |
| `dotbox new` 템플릿: `build.rs`, `assets/` 구조 | 엔진 담당 |

## 9. 단계

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| S1 프로젝트 | 실행 인자, 시작 화면, 새 프로젝트, 최근 목록, 개요, 포트 설정, `dotbox info`/`config` | `dotbox studio`로 연 프로젝트의 개요가 `dotbox info --json`과 같은 값을 보여 준다 |
| S2 에셋 저장 | 5장 합의, 효과음·스프라이트·아이콘 파일 저장/불러오기, 탐색기, 실행 취소, `assets check/build`, 템플릿 `build.rs` | Studio에서 만든 효과음과 스프라이트가 `dotbox run`으로 띄운 게임에 나온다 |
| S3 빌드·기기 | 진행 이벤트·취소, 실행/중지, 빌드·플래시 진행 표시, 문제 패널, 양쪽 시리얼 로그 | 빌드 오류를 누르면 파일이 열리고, 양쪽 플래시를 Studio에서 끝까지 할 수 있다 |
| S4 완성도 | 글꼴 에셋(기준선 정렬), 스프라이트 애니메이션·고급 도구, 외부 변경 감지, 장면 미리보기 | 숫자 글꼴로 점수를 그리는 게임을 Studio만으로 준비할 수 있다 |

S1은 엔진 쪽 변경이 작아 바로 시작할 수 있다. S2는 5장 합의와 엔진의 `Sprite` 타입이 먼저다.

## 10. 테스트

- `dotbox-tools`의 새 함수: 형식 해석·검사·생성, 프로젝트 정보, 설정 읽기·쓰기를 임시 디렉토리로 테스트한다.
  생성 결과는 같은 입력에서 바이트 단위로 같은지 확인한다.
- CLI 통합 테스트: 신규 명령의 종료 코드, `--json` 출력, 프로젝트 밖 실행 오류.
- 끝에서 끝까지: `dotbox new` → `assets new sound jump` → `assets build` → 생성된 게임이 `cargo test`를 통과.
- Studio: 편집 명령, 실행 취소, 파일 저장/불러오기 왕복, 탭 더티 상태를 GUI 없이 테스트한다.

## 미결 사항

- 프로젝트 이름 변경 지원 여부(패키지 이름·디렉토리까지 바꿀지).
- 스프라이트 색 팔레트 제한 여부(자유 RGB / 게임별 팔레트). 밝기 15~25%에서 구분되는 색만 허용할지.
- 감마 보정을 미리보기에 넣을지. 엔진의 감마·밝기 처리(아직 없음)가 정해진 뒤 맞춘다.
- 효과음 주파수 허용 범위. 실제 부저로 측정해 정한다.
- 글꼴 대체 글리프 모양과 한글 문자 집합 기본값.
- 파일 변경 감지 방식(`notify` crate 또는 주기적 확인).
