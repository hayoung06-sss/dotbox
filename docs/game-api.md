# 게임 API와 모듈 동기화 명세 (v0.1)

> 상태: **1단계 구현됨**(dotbox-core, dotbox-sim). 아이콘 메뉴, 기기 실행기(`dotbox-esp`)는 아직 없다.
> 동작을 바꿀 때는 이 문서를 먼저 고친다.

## 1. 범위

- 게임이 엔진에 제공하는 인터페이스(`Game` 트레잇)와 여러 게임 등록
- 두 모듈이 한 게임을 함께 실행하는 방식(마스터/슬레이브)과 모듈 간 메시지
- 한 모듈 안의 엔진 루프 순서
- 시뮬레이터와 테스트에서 이 구조를 재현하는 방법

역할 결정은 [pairing.md](pairing.md), 화면 레이아웃과 합체 상태는 [modes.md](modes.md), 오류 처리는 [errors.md](errors.md)를 따른다.

## 2. 실행 모델

3번째 탭(하드웨어 스펙) 4장의 전략을 그대로 따른다.

```
 오른쪽(슬레이브)                              왼쪽(마스터)
 ┌────────────────────┐   Input (매 틱)    ┌──────────────────────────────┐
 │ 조이스틱 샘플·처리 │ ─────────────────▶ │ 입력 합치기(P1 로컬, P2 원격)  │
 │                    │                    │ game.update(state, input)    │
 │                    │   State (매 틱)    │                              │
 │ render(state)      │ ◀───────────────── │ render(state)                │
 │ → 오른쪽 패널 출력 │                    │ → 왼쪽 패널 출력, 사운드      │
 └────────────────────┘                    └──────────────────────────────┘
```

- **게임 규칙은 마스터만 실행한다.** 슬레이브는 `update`를 부르지 않는다. 따라서 두 모듈의 결정성이 필요 없다.
- **상태를 통째로 보낸다.** 마스터는 매 틱 게임 상태 전체를 보낸다. 패킷이 몇 개 빠져도 다음 패킷으로 회복된다.
- **두 모듈이 같은 `render`를 부른다.** 각자 32×16 프레임 전체를 그린 뒤 자기 패널(16×16)만 출력한다.
- 플레이어 번호는 모듈과 같다. 왼쪽 조이스틱이 P1, 오른쪽 조이스틱이 P2다.

## 3. `Game` 트레잇

```rust
pub trait Game: 'static {
    /// 두 모듈이 화면을 그리는 데 필요한 모든 것. 매 틱 마스터가 슬레이브로 보낸다.
    type State: GameState;

    /// 게임 정보. 등록할 때 한 번 읽는다.
    fn config(&self) -> GameConfig;

    /// 첫 상태를 만든다. 마스터에서만, 게임을 시작할 때마다 부른다.
    fn init(&mut self, ctx: &mut Context) -> Self::State;

    /// 한 틱을 진행한다. 마스터에서만 부른다.
    fn update(&mut self, state: &mut Self::State, input: &Input, ctx: &mut Context);

    /// 상태를 그린다. 양쪽 모듈에서 부른다. 엔진이 비운 프레임을 넘긴다.
    fn render(state: &Self::State, frame: &mut FrameBuffer);
}
```

### 3.1 상태 나누기 규칙

| 어디에 둘까 | 내용 | 예 |
|---|---|---|
| `State` | **화면에 보이는 데 필요한 것 전부** | 뱀 몸통, 공 위치, 패들, 점수, 현재 단계(타이틀/플레이/결과) |
| `Self`(게임 객체) | 마스터만 쓰고 화면과 무관한 것 | 내부 타이머, AI 계산용 값 |

- `render`는 `&self`를 받지 않는 연관 함수다. **`State`만 보고 그려야 한다는 규칙을 타입으로 강제**한다.
  슬레이브의 게임 객체는 `init`/`update`가 불리지 않기 때문이다.
- 그리는 데 필요한 정적 데이터(스프라이트, 글꼴)는 `const`/`static`으로 두고 `render`에서 직접 쓴다.

### 3.2 `GameState`와 직렬화

```rust
pub trait GameState: Sized {
    /// 인코딩한 최대 크기. MAX_STATE_BYTES 이하여야 한다.
    const MAX_BYTES: usize;
    fn encode(&self, out: &mut StateWriter<'_>) -> Result<()>;
    fn decode(input: &mut StateReader<'_>) -> Result<Self>;
}
```

- `MAX_STATE_BYTES = 200`. ESP-NOW 한 패킷(250바이트)에 메시지 헤더와 여유를 뺀 값이다.
- `StateWriter`/`StateReader`는 고정 버퍼 커서다. `u8`/`i8`/`u16`/`i16`/`u32`(리틀 엔디언), `bool`, 바이트 배열을 읽고 쓴다.
  힙 할당을 하지 않는다. 범위를 넘으면 `Error::InvalidArgument`를 돌려준다.
- 크기 예: 스네이크는 32×16 칸 점유 비트맵 64바이트 + 좌표·방향·점수 10바이트 남짓. 핑퐁은 20바이트 이하.
- 게임을 등록할 때 `MAX_BYTES > MAX_STATE_BYTES`이면 실패한다(PC 테스트에서도 걸린다).

### 3.3 `GameConfig`

```rust
pub struct GameConfig {
    /// 게임 이름. ASCII. 기록 저장 키로도 쓴다.
    pub name: &'static str,
    /// 시작 레이아웃. Context::set_layout으로 바꿀 수 있다.
    pub layout: ScreenLayout,
    /// 메뉴에 보일 16×16 아이콘. 없으면 기본 아이콘.
    pub icon: Option<&'static Icon>,
}
```

`Icon`은 16×16 `Rgb` 배열(행 우선)이다.

### 3.4 `Context` (마스터 전용 서비스)

| 기능 | 설명 |
|---|---|
| `tick()` | 게임을 시작한 뒤 진행한 틱 수 |
| `random_u32()` / `random_below(n)` | 난수. 시드는 연결할 때마다 플랫폼이 준 값으로 새로 정한다 |
| `play_sound(&'static Sound)` | 효과음. 왼쪽 부저에서 낸다. 소리 하나만 재생하며 새 요청이 이전 소리를 끊는다 |
| `set_layout(ScreenLayout)` | 레이아웃 변경. 다음 `State` 메시지로 슬레이브에 전달된다 |
| `exit()` | 게임을 끝낸다. 메뉴로 돌아간다(4장) |

`Sound`는 `&'static [Note]`이고 `Note { freq_hz: u16, duration_ms: u16 }`이다. 주파수 0은 쉼표다.

## 4. 여러 게임과 메뉴

펌웨어 하나에 게임 여러 개를 넣을 수 있다.

```rust
dotbox_sim::run(|| Games::new().with(Snake::new()).with(Pong::new()))
dotbox_sim::run(Snake::new)   // 게임 하나는 생성 함수를 그대로 넘긴다
```

- 실행기는 게임 목록이 아니라 **게임 목록을 만드는 함수**를 받는다. 시뮬레이터는 마스터와 슬레이브 엔진을
  한 프로세스에서 돌려 목록이 두 벌 필요하기 때문이다. 기기 실행기(`dotbox_esp::run`)도 같은 형태를 받는다.

- `Games`는 등록 순서대로 게임을 담는다. 게임 객체는 등록할 때 한 번 만들고 엔진이 끝날 때까지 유지한다.
  게임을 바꿀 때나 매 틱에는 할당하지 않는다.
- 엔진 안에서는 타입을 지운 어댑터로 감싸 한 목록에 둔다. 게임 작성자는 `Game` 트레잇만 구현한다.
- 같은 이미지라 등록 순서가 양쪽 모듈에서 같다. 그래서 `State` 메시지는 게임을 등록 번호(1바이트)로 가리킨다.
- **게임이 하나면** 메뉴 없이 바로 시작하고, `exit()`하면 처음부터 다시 시작한다.
- **게임이 여럿이면** 메뉴에서 고른다. 메뉴는 엔진에 내장되어 있고, 같은 동기화 경로(`State` 메시지)를 쓴다.
  - 왼쪽 패널에 선택한 게임의 아이콘, 오른쪽 패널에 다음 게임의 아이콘을 보여 준다.
  - 어느 플레이어든 좌우로 고르고 버튼으로 시작한다.
- 세션은 연결마다 새로 정한다. 게임을 바꿀 때는 `State`의 게임 번호로 슬레이브가 따라 바꾼다.
- 강제 종료 조작(두 플레이어가 버튼을 2초 누르기 등)은 메뉴 구현 단계에서 정한다.

**구현 단계**: 1단계에서는 목록 등록, 게임 번호 전송, `exit()`(맨 처음 게임 다시 시작)까지 만든다.
아이콘 메뉴는 스네이크·핑퐁이 생긴 뒤 추가한다. 그전까지 게임이 여럿이면 첫 게임만 실행된다.

## 5. 입력

### 5.1 게임이 받는 입력

```rust
pub struct Input {
    pub players: [PlayerInput; 2],   // [P1(왼쪽), P2(오른쪽)]
    pub dock: DockState,             // Docked | Undocked | Unknown (modes.md 4장)
}

pub struct PlayerInput {
    /// 데드존과 히스테리시스를 거친 4방향. 중립이면 None.
    pub direction: Option<Direction>,
    /// 이번 틱에 새로 들어간 방향(None → Some 또는 방향 전환).
    pub direction_pressed: Option<Direction>,
    /// 아날로그 값 -100..=100. 오른쪽·아래가 +. 데드존 안은 0.
    pub axis_x: i8,
    pub axis_y: i8,
    pub button: ButtonState,   // held, pressed, released
    /// 원격 입력이 끊겨 중립으로 바꾼 상태인지(P2에만 해당).
    pub stale: bool,
}
```

### 5.2 입력 처리 (각 모듈에서)

조이스틱 원시 값(`RawInput`)은 **그 조이스틱이 달린 모듈**에서 처리한다. 슬레이브는 처리한 결과를 보낸다.

| 항목 | 규칙 | 기본값 |
|---|---|---|
| 중립 보정 | 처음 샘플 여러 개의 평균을 중앙값으로 잡는다. 그동안은 중립이다 | 샘플 8개 |
| 아날로그 | 중앙 기준 -100..=100. 데드존 밖을 0..=100으로 다시 늘린다 | 데드존 20% |
| 방향 | 데드존을 넘으면 변위가 큰 축의 방향. 두 축이 같으면 이전 방향 유지. 풀리는 기준은 더 낮다 | 진입 20%, 해제 15% |
| 버튼 | 원시 상태가 일정 시간 유지되어야 바꾼다 | 디바운스 10 ms |

값은 실기기에서 다시 맞춘다. 축 방향(위가 + 인지 −인지)은 조이스틱 장착 방향에 따라 보드 설정으로 뒤집는다.

### 5.3 이벤트 규칙

- `pressed`/`released`/`direction_pressed`는 **한 틱에서 한 번만** 참이다. 따라잡기로 한 루프에서 여러 틱을 돌면 첫 틱에만 준다.
- 한 틱 사이에 눌렀다 떼면 `pressed`와 `released`가 함께 참일 수 있다.
- 게임이 시작된 직후에는, 이미 누르고 있던 버튼으로 `pressed`를 만들지 않는다.

## 6. 엔진 루프 (한 모듈)

```
loop {
    1. 링크 수신: 메시지를 최대 8개까지 꺼내 처리한다(핸드셰이크, Input, State)
    2. 로컬 입력 샘플링과 처리
    3. 틱 계산: ticks = ticker.advance(now)
    4. 마스터:  틱마다 입력 합치기 → update.  틱이 하나라도 돌았으면 State 송신
       슬레이브: 틱이 돌았으면 Input 송신.  연결 전이면 200 ms마다 Hello 송신
    5. 렌더: 새 상태가 있으면 render → 자기 패널 복사 → Display 출력
    6. 사운드 갱신
}
```

- **틱**: `TICK_MS = 16`(약 62.5 Hz). 3번째 탭의 60fps 목표에 맞춘다. WS2812B 256개 전송은 약 7.7 ms라 한 틱 안에 들어간다.
- 한 번의 반복은 `Engine::step(now_ms, io)`이다. 플랫폼 실행기는 이 함수를 반복해서 부르고 사이에 잠깐 양보한다.
- 연결 전(`Searching`/`Rejected`)에는 게임을 진행하지 않고 화면을 끈다. 연결이 맺어지면 마스터가 게임을 시작한다.
- 연결이 끊기면(6.4) 마스터는 게임을 멈추고 `Searching`으로 돌아간다. 다시 연결되면 처음부터 시작한다.
- 밝기는 엔진이 시작할 때 `Display::set_brightness_percent`로 한 번 설정한다. 기본 20%(허용 15~25%).
- 매 틱 경로와 렌더 경로에서는 힙 할당을 하지 않는다.

## 7. 모듈 간 메시지

### 7.1 공통 헤더 (6바이트)

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 2 | 매직 `b"DB"` |
| 2 | 1 | 메시지 종류 |
| 3 | 1 | 세션 ID. 연결마다 마스터가 새로 정한다(1~255). 연결 전 메시지에서는 0 |
| 4 | 2 | 순번(u16, 리틀 엔디언). 송신자마다 1씩 증가하고 순환한다 |

| 종류 | 값 | 방향 | 내용 |
|---|---|---|---|
| `Hello` | 0x01 | 슬레이브 → 마스터 | 프로토콜 버전(u16), 역할(u8), build_id(8) |
| `Accept` | 0x02 | 마스터 → 슬레이브 | 없음. 헤더의 세션 ID가 새 세션이다 |
| `Reject` | 0x03 | 마스터 → 슬레이브 | 사유(u8): 1 역할 충돌, 2 프로토콜 불일치, 3 빌드 불일치 |
| `Input` | 0x10 | 슬레이브 → 마스터 | 7.2 |
| `State` | 0x11 | 마스터 → 슬레이브 | 7.3 |

- `Hello`는 연결 전인 슬레이브만 보낸다. 마스터가 재부팅해도 슬레이브가 끊김을 감지하고 다시 `Hello`를 보내므로 연결이 복구된다.
- 받는 쪽은 세션 ID가 현재 세션과 다른 `Input`/`State`를 버린다.
- 순번은 순환 비교(`seq.wrapping_sub(last) as i16 > 0`)로 새 것만 받는다.
- ESP-NOW 프레임에 무결성 검사가 있으므로 별도 체크섬은 두지 않는다.

### 7.2 `Input` (7바이트)

| 크기 | 내용 |
|---|---|
| 1 | 방향(0 = 없음, 1~4 = 위·아래·왼쪽·오른쪽) |
| 1 + 1 | `axis_x`, `axis_y` (i8) |
| 1 | 버튼 유지 여부 |
| 1 | 버튼 누름 누적 횟수(u8, 순환) |
| 1 | 버튼 뗌 누적 횟수(u8, 순환) |
| 1 | 예약(0) |

- 이벤트를 **누적 횟수**로 보낸다. 마스터는 이전 값과의 차이로 `pressed`/`released`를 만든다. 패킷이 빠져도 누른 사실이 남는다.
- 마스터가 **250 ms** 동안 `Input`을 받지 못하면 P2를 중립으로 바꾸고 `stale = true`로 표시한다.

### 7.3 `State` (2 + 상태 바이트)

| 크기 | 내용 |
|---|---|
| 1 | 실행 중인 게임 번호(등록 순서) |
| 1 | 현재 `ScreenLayout`(0 Wide, 1 Mirrored) |
| 가변 | `GameState::encode` 결과(최대 `MAX_STATE_BYTES`) |

슬레이브는 가장 최근 `State`만 그린다.

### 7.4 연결 끊김

- 마스터는 **500 ms** 동안 `Input`을 받지 못하면, 슬레이브는 500 ms 동안 `State`를 받지 못하면 `Searching`으로 돌아간다.

## 8. 시뮬레이터 (`dotbox-sim`)

- 한 프로세스에서 **마스터 엔진과 슬레이브 엔진을 둘 다 돌린다.** 둘은 메모리 안의 가짜 `Link`로 이어진다.
  기기와 같은 경로(직렬화 → 전송 → 역직렬화 → 렌더)를 PC에서 검증한다.
- 창 하나에 두 패널을 그린다. 왼쪽은 마스터 엔진, 오른쪽은 슬레이브 엔진의 출력이다. 두 패널 사이에 간격을 둔다.
- 키보드:

| | 왼쪽 모듈(P1) | 오른쪽 모듈(P2) |
|---|---|---|
| 방향 | W A S D | ↑ ← ↓ → |
| 버튼 | Space | Enter |

  `F2`는 두 모듈의 연결을 끊었다 잇는다. `Esc`는 종료한다.
- 환경 변수 `DOTBOX_SIM_HEADLESS_MS=<ms>`를 주면 창 없이 그 시간만큼 돌리고 끝낸다(자동 테스트용).
- 창 라이브러리는 `minifb`.

## 9. 테스트 지원

`dotbox_core::testing::Harness`로 화면 없이 게임 하나를 돌린다.

- 입력을 넣어 틱을 진행하고 상태와 프레임을 확인한다.
- 매 틱 `State`를 인코딩·디코딩해 다시 인코딩한 결과가 같은지 확인한다.

`dotbox_core::testing::loopback_pair()`는 메모리 안의 `Link` 한 쌍이다. 두 엔진을 이어 동기화 경로를 테스트한다.

## 10. 결정 사항

| 항목 | 결정 |
|---|---|
| 펌웨어당 게임 수 | 여럿. 하나면 메뉴 없이 바로 시작 |
| 틱 주기 | 16 ms |
| 원격 입력 만료 | 250 ms, 연결 끊김 500 ms |
| 입력 처리 기본값 | 데드존 20%, 해제 15%, 디바운스 10 ms |

## 미결 사항

- 아이콘 메뉴와 강제 종료 조작(스네이크·핑퐁 이후).
- 모듈 하나만으로 게임을 돌리는 개발용 모드(하드웨어 로드맵 1단계 검증용).
- 연결이 끊긴 뒤 진행 중인 판을 이어서 하기.
- 오른쪽 부저로 소리 내기, `Hello`에 하드웨어 구성 싣기(modes.md 6.1).
